# 수집 범위와 조건 판정이 결론을 결정한다

## 1. 조건을 판정 가능한 형태로 정리한다

내부적으로 조건마다 다음을 기록한다. 단순한 요청에서 이 기록을 긴 설문이나 사용자용 표로
모두 노출할 필요는 없다.

- 원문 의미와 비교 연산: 이상·초과·이하·미만, 범위, AND·OR·제외.
- 필수인지 선호인지, 단지·건물·호·계약 중 어느 단위인지.
- ‘하나라도 존재’, ‘전부’, ‘몇 개 이상’, ‘비중·평균’ 중 무엇인지.
- 근거 상품·필드, 가격 개념·면적 단위·시점, 필요한 연결·계산.

범위나 ‘가까운’, ‘저렴한’ 같은 표현이 후보를 바꾸고 문맥으로 해결되지 않을 때만 묻는다.
특정 숫자를 보편적인 기본값으로 넣지 않는다. 나머지 식별·가용 필드 확인은 계속할 수 있다.
이미 지정된 조건과 출력 형식은 존중한다.

## 2. 식별과 후보 수집을 분리한다

이름 검색은 제한된 추천 후보를 반환한다. `has_next=false`라도 그 지역의 모든 단지를
찾았다는 뜻이 아니다. 확정한 지역 코드로 지역 단지 목록을 조회한다.

여러 지역이나 분할 범위를 합칠 때는 범위를 기록하고 단지 키로 중복 제거한다. 제외 지역도
원래 공간 수준으로 처리한다. 동 요청을 시군구로 바꾸거나 역 주변을 역이 위치한 한 동으로
축소하지 않는다. 특정 역까지의 거리는 ‘가장 가까운 역의 이름·거리’만으로 항상 판정할 수
없다. 다른 역이 더 가깝더라도 요청한 역 근처일 수 있으므로 필요한 위치 근거가 없으면 미확인이다.

## 3. 확정적으로 탈락하는 후보부터 줄인다

필수 단지 조건으로 확실히 탈락한 후보에는 상세 호출을 추가하지 않는다. OR 분기의 하나가
실패했거나 선호가 충족되지 않은 것만으로는 탈락시키지 않는다. 결측도 곧바로 실패가 아니다.
남은 후보에 대해서만 조건별 상세 근거를 조회한다.

현재 응답과 계약에서 페이지 끝·정렬·한도를 확인한다. 같은 조회 결과는 세션 안에서 재사용하고,
필요한 필드만 선택하되 식별자·판정 필드·기준시점은 보존한다. 비용을 줄이려고 먼저 나온
후보 몇 개만 남긴 뒤 최적·전체 결과라고 부르지 않는다.

후보별 상세 조회 전에 판정과 완료 확인에 필요한 필드를 정한다. 이미 받은 응답에 필요한 근거가
있으면 판정·정렬·요약·출력 검증에 재사용한다. 필요한 필드나 범위가 없거나 요청이 실패·절단됐거나
사용자가 갱신을 요구한 경우에만 부족한 범위를 다시 조회한다.

## 4. 종료에는 그 결론에 맞는 근거가 필요하다

| 주장 | 충분한 종료 근거 |
|---|---|
| 지역에서 조건에 맞는 단지를 모두 찾았다 | 요청한 모집단을 끝까지 판정했거나, 남은 행은 논리적으로 충족할 수 없음을 입증했다. |
| 특정 호·면적·계약이 하나라도 있는 단지다 | 관련 조건을 동시에 만족하는 실제 근거 행 하나를 확인했다. 그 단지의 존재 조건만 종료한다. |
| 해당 조건의 호·계약이 없다 | 그 조건을 확인할 전체 범위를 조회했다. 일부 페이지에 없다는 사실은 충분하지 않다. |
| 비중·평균·전체 건수가 기준을 넘는다 | 조건의 분모가 되는 범위를 확보했다. 일부 조회면 그 표본의 값으로만 표시한다. |
| 상위 후보 N개다 | 명시한 정렬 기준에서 미조회 후보가 이 N개를 앞설 수 없고 동률 처리가 설명된다. |
| 조건에 맞는 예시 N개다 | N개의 충족 근거를 확인했다. 나머지 미조회 범위와 최상위·전체가 아니라는 사실을 밝힌다. |

최신 유효값은 날짜 내림차순으로 조회하고 취소·범위 밖 행을 건너뛴 뒤 처음 확인한 유효 날짜를
기준으로 삼는다. 같은 날짜의 행이 페이지 끝에 걸릴 가능성이 있을 때만 다음 페이지에서 그 날짜까지
확인하고, 더 오래된 날짜로 넘어가면 종료한다. 반대로 일치 행이 없다고 결론내리려면 해당 범위를
끝까지 확인해야 한다.

서버 정렬과 필수 임계값이 맞물리면 안전하게 일찍 끝낼 수 있다. 예를 들어 세대수 내림차순에서
필수 최소 세대수보다 작은 **실제 값**에 도달하면 이후의 알려진 값은 그 조건을 통과하지 못한다.
정렬의 일관성·null 배치와 미확인 후보 처리도 확인한다. 이 방식은 OR의 다른 분기로 통과할 수
있거나 로컬 파생 지표로 순위를 매기는 경우에는 그대로 적용할 수 없다. null 구간은 탈락이 아닌
미확인 범위로 남길 수 있으므로 ‘모든 단지의 판정 완료’라고 쓰지 않는다.

페이지 상한에 닿으면 현재 상품이 지원하는 서로 빠짐없는 하위 지역·건물·필터 구간으로
분할할 수 있는지 검토한다. 분할 키는 상품마다 다르다. 실거래를 지원하지 않는 건물 키로
쪼개지 않는다. 값·날짜가 겹치는 구간은 근거 식별자로 대사한다. 완전한 분할을 확보하지 못하면
부분 결과를 제공한다. 사용자 범위를 줄이는 것은 조건 변경이지 내부 최적화가 아니다.

권한·사용량·요청 제한이나 일시 오류가 생기면 이미 확인한 결과와 중단 지점을 보존한다.
같은 실패 호출을 반복하거나 부분 실패를 빈 결과로 바꾸지 않는다. 공유 사용량 제한이면
해당 후보만 건너뛰지 말고, 현재 작업에서 같은 한도를 사용하는 나머지 후보·페이지 조회도
중단한다. 수집 코드를 작성할 때는 이 중단이 바깥 반복문까지 전달되게 한다. 제한의 적용
범위는 응답·상품 계약으로 확인하며, 한도 수치나 대기 시간을 고정하지 않는다. 전체 후보의
모집단 누락과 개별 후보의 상세 미확인은 별도로 기록한다.

## 5. 같은 대상에서 조건을 함께 확인한다

‘전용면적 범위 안이면서 특정 층 이상이고 산출시세가 예산 이내인 호가 있는 단지’는 다음을
뜻한다.

```text
exists 호: 면적조건(호) AND 층조건(호) AND 가격조건(같은 호)
```

면적은 A호, 가격은 B호에서 가져와 합치면 안 된다. 반대로 사용자가 ‘소형과 중형이 모두
있는 단지’라고 하면 서로 다른 구성 행에서 각각 존재해도 된다. AND라는 단어만으로 모든
조건이 같은 호를 가리킨다고 강제하지 말고 원래 의미를 보존한다.

| 판정 | 처리 |
|---|---|
| AND | 하나라도 확실히 거짓이면 미충족. 모두 참이면 충족. 나머지는 확인 불가. |
| OR | 하나라도 확실히 참이면 충족. 모두 거짓이면 미충족. 나머지는 확인 불가. |
| 제외 / NOT | 참·거짓만 반전한다. 확인 불가는 그대로다. |
| 존재 | 일치 행을 찾으면 충족. 끝까지 조회해 일치 행이 없으면 미충족. 아직 남으면 확인 불가. |
| 선호 | 필수 판정을 바꾸지 않는다. 선호 근거와 상충 관계를 표시하거나 공개한 순서로 정렬한다. |

잘못된 식별자·유형·날짜·면적의 반환 행은 근거에서 제외하고 계약 이상을 기록한다. 분모가
0이거나 누락됐으면 비율은 미확인이다. 반올림한 표시값이 아니라 원래 값으로 임계값을 판정한다.

## 6. 조회 범위가 결과 옆에 보이게 쓴다

충족 후보에는 주요 조건의 실제 값과 기준시점을 붙인다. 미확인 후보는 충족 목록과 구분하고
어느 조건이 왜 확인되지 않았는지 적는다. 확실히 탈락한 모든 단지를 길게 나열할 필요는 없다.

조회 범위에는 요청 지역·유형·시점, 확인한 모집단과 남은 범위, 적용한 조건, 정렬 기준,
표시한 결과 범위를 필요한 만큼 담는다. 완료·부분 확인·조회 불가를 구분한다. ‘확인된 충족
후보 없음’과 ‘요청 범위 전체에 충족 후보 없음’은 다른 결론이다. 단지 후보 수, 조회한 행 수,
표시한 후보 수를 섞어 쓰지 않는다.

HTML의 `outcome`, `coverage`, `criteria`, `sections`, `sources`는 이 의미를 담는 표시 자료다.
템플릿은 조건을 다시 계산하거나 합격 여부를 추정하지 않는다. 데이터를 판정한 뒤 결과를 넣는다.
