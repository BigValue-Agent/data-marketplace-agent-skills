# Comparison Patterns

아래 패턴은 자주 나오는 비교 의도를 데이터 근거에 연결하는 예시다. 질문에 맞는 패턴만
사용하고 필요하면 일부를 조합한다. 다섯 패턴은 고정 호출 순서가 아니다.

## 1. 단지 간 실거주 여건

예: `리센츠랑 헬리오시티 중 실거주하기 어디가 더 나아?`

**비교 의도:** 규모, 연식, 주차, 교통·학교·생활시설 접근성에서 대상별 장점과 제약을 본다.

**가능한 근거:** 대상 식별 + 단지 상세.

**힌트:**

- 세대수·연식·난방처럼 원자료는 나란히 놓고, 주차는 세대당 대수처럼 같은 단지 행에서만
  의미 있는 파생값을 만들 수 있다.
- 지하철·병원·공원 거리는 서로 같은 단위로 비교하되 실제 이동시간으로 바꾸지 않는다.
- 사용자가 우선순위를 주지 않았다면 하나의 생활점수보다 항목별 우위와 상충 관계를 보여준다.
- 학교명은 사실로 제시할 수 있지만 학군 서열이나 만족도를 만들지 않는다.

## 2. 지역 간 시장 규모와 활동

예: `잠실동과 반포동 아파트 시장의 규모와 최근 거래 분위기를 비교해줘.`

**비교 의도:** 같은 공간 수준에서 단지 수, 세대수·연식 분포, 최근 거래 관측 범위를 비교한다.

**가능한 근거:** 대상별 법정동 검색 + 지역 단지 목록.

**힌트:**

1. 같은 이름의 다른 지역을 제외하고 비교할 법정동 또는 시군구 범위를 확정한다.
2. 두 지역 모두 필요한 페이지를 끝까지 수집한 경우에만 전체 합계·분포를 비교한다.
3. 아파트·오피스텔·연립다세대는 유형을 나누고, 같은 유형끼리 비교한다.
4. 최근 6개월 단지 요약은 거래 활동을 비교하는 빠른 근거다. 면적 혼합 평균가는 지역 가격
   수준의 직접 비교로 쓰지 않는다.

## 3. 지역 안 단일 기준 순위

예: `잠실동에서 최근 6개월 매매가 활발한 아파트 순위 알려줘.`

**비교 의도:** 한 모집단을 사용자가 지정한 한 기준과 방향으로 정렬한다.

**가능한 근거:** 법정동 검색 + 지역 단지 목록. 기준은 규모·연식·역 거리·최근 매매 건수 등
단지 상세가 제공하는 값에서 고른다.

**힌트:**

- 순위 제목에 지역, 주거 유형, 기간, 지표와 정렬 방향을 함께 쓴다.
- 전체 목록을 수집하지 않았다면 전체 순위가 아니라 상위 N개라고 표시한다.
- 결측값은 0이나 꼴찌로 만들지 않고 별도 표시한다. 동률은 그대로 두거나 공개한 보조 기준만
  사용한다.
- `대장`, `가장 좋은 곳`처럼 기준이 여러 개인 말에는 임의 가격순 기본값을 넣지 않는다.
  문맥상 중요한 몇 개 축을 나눠 보여 주거나 사용자의 의도가 명확할 때만 한 기준을 택한다.

## 4. 같은 면적의 가격 비교

예: `래미안 원베일리와 아크로리버파크 전용 84㎡급의 최근 실거래와 현재 산출시세를 비교해줘.`

**비교 의도:** 대상별로 같은 거래 유형·전용면적 범위의 과거 계약과 현재 추정 수준을 비교한다.

**가능한 근거:** 대상 식별 + 면적을 맞춘 실거래. 현재 가격 근거가 필요하면 산출시세를 별도
축으로 추가한다.

**힌트:**

1. 전용면적 범위를 먼저 정하고 같은 거래 유형·기간의 취소되지 않은 계약만 모은다.
2. 사용자가 호를 지정했으면 각 대상의 특정 `jpk` 행을 1:1로 비교한다.
3. 단지·면적대를 비교하면 같은 기준월·연도와 면적 범위의 호별 분포를 모아 중앙값,
   관측 범위, 표본 수를 비교한다. 임의의 한 호나 일부 페이지 평균을 단지 대표값으로
   사용하지 않는다.
4. 산출시세는 호별 `estimated_price`를 집계하고, 각 호의 하한·상한은 해당 호의 범위로만
   해석한다. 공시가격은 같은 공시연도로 맞추고 면적 필터가 없으면 수집한 행을 면적으로
   다시 거른다.
5. `has_next`가 끝날 때까지 모으되, 허용된 최대 `offset`에서도 남으면 필터로 좁히거나
   관련된 모든 `ppk`별로 나눠 조회한 뒤 합친다.
   그래도 전체를 모을 수 없으면 `절단 표본`으로 밝히고 단지 전체를 대표하는 값으로 단정하지 않는다.
6. 실거래·산출시세·공시가격은 평균내지 않고 서로 다른 가격 축으로 병렬 표시한다.

## 5. 평형·면적 구성 비교

예: `리센츠와 헬리오시티의 평형 구성과 주력 면적대를 비교해줘.`

**비교 의도:** 각 단지의 공급 평형·타입·전용면적별 수량과 다양성을 비교한다.

**가능한 근거:** 대상별 건물 상세의 `units_summary`.

**힌트:**

- 건물별 요약을 펼쳐 같은 공급 평형·타입·전용면적별 수량을 합한다.
- 각 대상의 구성비 분모는 그 대상의 `units_summary` 수량 합계다. 단지 세대수나 호수와
  다르면 전체 재고라고 단정하지 말고 `집계 가능한 구성`과 분모를 밝힌다. 차이를 임의로
  보정하지 않는다.
- 공급 평형 라벨과 전용면적을 함께 보여 준다. 공급 평형이 같아도 전용면적이 다를 수 있고,
  다른 평형의 전용면적이 겹칠 수도 있다.
- 특정 호·층이 질문의 핵심이 아니면 호실 상세를 호출하지 않는다.

## 패턴을 벗어난 비교

- 대상이 둘 이상이고 비교 가능한 공통 축이 있으면 단지·지역·평형·호에 한정하지 않고 같은
  절차를 적용할 수 있다.
- 사용자가 이미 비교표나 점수식을 주면 그 구조를 우선한다. 데이터에 없는 항목은 비워 두고
  대체값을 만들지 않는다.
- 순위가 의미 없는 질문은 승자를 만들지 말고 차이, 우위 조건, 선택 기준으로 답한다.
- 근거가 부족하면 비교 가능한 사실과 판단할 수 없는 항목을 분리한다.
