# Residential Diagnostic Report

빅밸류 데이터에서 질문에 필요한 근거만 골라 한국 주거 부동산의 상태와 의미를 진단한다.
특정 단지·동·호·평형이나 정해진 상품 조합을 전제로 하지 않는다.

## 결과 원칙

- 사용자가 원하는 대상과 관점에 맞춰 한국어 리포트를 작성한다.
- 별도 형식 요청이 없으면 핵심 판단, 근거, 해석 한계가 읽히는 간결한 Markdown으로 답한다.
- HTML 카드나 파일형 리포트가 필요하면 `assets/report.html`을 사용한다. 조회 근거가 없는
  섹션은 추가하지 않는다.
- 같은 수치를 핵심 카드·표·본문에 반복하지 말고 가장 빨리 이해할 수 있는 표현 하나를 고른다.
  핵심 진단과 근거로 의미가 충분하면 같은 해석을 별도 섹션으로 다시 만들지 않는다.
- 수집·계산·제외 처리는 내부에서 검증한다. 사용자 본문에는 진단을 바꾸는 근거와 한계만
  한 번씩 쓰고, 페이지 수·필터 적용·반환 행 같은 실행 과정은 근거 파일이나 기술 부록으로
  분리한다.
- 관측값과 해석을 구분하고, 결론마다 어떤 범위와 기준시점의 근거인지 드러낸다.

## 데이터 접근

빅밸류 데이터는 현재 환경에 연결된 MCP 상품 도구 또는 공개 API 중 사용 가능한 경로로
조회한다. 경로 선택과 호출 방식은 에이전트가 판단한다. API 계약이 필요하면 먼저
`https://datamarket.bigvalue.ai/llms.txt`를 읽고, 여기서 연결하는 최신 상품 문서만 따른다.
인증 방식이나 자격 증명 요청 절차를 이 스킬에서 고정하지 않는다.

실제 데이터를 읽을 수 없는 환경에서는 수치를 추측하거나 예시값으로 진단하지 말고,
필요한 데이터에 접근하지 못했다고 짧게 알린다.

## 진행 순서

1. **진단 질문을 정한다.** 사용자의 말에서 대상, 공간 범위, 주거 유형, 기간, 궁금한
   판단을 추출한다. 빠진 조건은 데이터가 제공하는 범위 안에서 합리적으로 정하되 리포트에
   밝힌다. 후보가 여럿이고 대상 선택이 결론을 바꾸는 경우에만 선택지를 확인한다.
2. **최소 상품을 고른다.** `references/product-guide.md`에서 질문에 직접 근거가 되는
   상품만 선택한다. 지도 표현이 없는 리포트에 경계·마커를 관성적으로 호출하거나,
   평형·동·호가 필요하지 않은 질문을 상세 단계로 내리지 않는다.
3. **식별자와 범위를 잇는다.** 단지는 검색 결과의 `complex_key`, 지역은 법정동 코드,
   건물은 `ppk`, 호는 `jpk`를 문자열로 유지하고 집계·조인은 이 식별자로 수행한다. 이름은
   표시용으로만 쓰며 서로 다른 단위의 행을 같은 모집단처럼 합치지 않는다.
4. **근거를 충분히 모은다.** 전체를 주장하거나 통계를 계산할 때는 지원 범위 안에서
   페이지를 끝까지 수집한다. 일부만 조회했다면 표본·상위 일부·조회 범위를 명시한다.
5. **비교 가능한 값만 해석한다.** 기준월, 주거 유형, 거래 유형, 면적 범위를 맞춘다.
   맞출 수 없으면 나란히 설명할 수는 있어도 하나의 평균·증감·점수로 합치지 않는다.
6. **진단을 쓴다.** 먼저 한두 문장으로 상태를 판단하고, 그 판단을 지지하는 핵심 근거와
   반대 신호 또는 한계를 필요한 곳에 한 번씩 제시한다. 사용한 데이터 출처와 기준시점을
   밝히고, 데이터가 말하지 않는 원인·전망·생활시간은 추정하지 않는다.

대표 조합과 계산 주의점이 필요할 때만 `references/diagnostic-patterns.md`를 읽는다. 이
파일의 사례는 선택 가능한 패턴이며 고정 호출 순서가 아니다.

## 반드시 지킬 데이터 의미

- `standard_ym` 등 상품의 기준시점을 우선한다. 오늘 날짜를 데이터 기준월처럼 쓰지 않는다.
  기준시점과 실제 집계 기간을 구분하고, 기간은 응답과 상품 계약으로 확인해 시작·종료를
  표시한다. 직접 집계했다면 실제 적용한 기간을 쓰고, 확인되지 않은 기간은 추정하지 않는다.
- 매매·전세·월세는 가격 필드의 의미가 다르므로 분리한다. 취소 거래는 유효 거래 통계에서
  제외하고, 신고 지연 가능성을 필요할 때 밝힌다.
- 단지 전체 실거래 가격은 여러 면적이 섞일 수 있다. 거래량 분위기는 볼 수 있지만 가격
  수준·등락을 말하려면 면적 구성을 맞추거나 혼합 범위임을 명시한다.
- 최근 6개월 단지 요약은 단지 전체 요약이다. 특정 평형·동·호의 값으로 해석하지 않는다.
- 산출시세는 최신 월 스냅샷, 공시가격은 연간 공시 기준값, 실거래는 과거 계약이다. 세 값을
  평균내거나 하나의 정답 가격으로 합치지 않는다.
- 단지 전체 평형별 수량·구성비는 제공하지 않는다. 이를 복원하려고 전체 호실을 열거하거나
  일부 호실·거래를 전체 주택 구성으로 해석하지 않는다.
- 거리값은 직선 또는 상품이 정의한 거리다. 도보시간·통학 안전·상권 품질로 바꾸지 않는다.
- 수치 반올림은 표시용으로만 사용한다. 거리·가격·면적·비율의 '이내·이상·초과' 등 경계
  판단은 원값으로 하고, 요약 문장에서도 그 판단을 바꾸지 않는다.
- 결측값은 0이 아니다. 조회되지 않은 사실, 원인, 미래 전망을 만들어내지 않는다.
- 화면에 API slug, 영문 필드명, 내부 식별자, 인증 정보가 보이지 않게 한다.

## 완료 전 확인

- 질문의 대상·필터 범위와 반환 행의 식별자·유형·날짜·면적이 일치하는가? 범위 밖 행은
  집계에서 제외하고 계약 이상을 밝혔는가?
- 결론이 실제 조회값으로 뒷받침되고 관측과 해석이 구분되는가?
- 면적·주거 유형·거래 유형·기준시점이 섞여 생긴 가짜 평균이나 추세가 없는가?
- 부분 조회, 결측, 신고 지연, 스냅샷 한계를 필요한 곳에 표시했는가?
- 특정 단지·평형·동·호가 필요하지 않은 질문에 그 경로를 강제하지 않았는가?
