# Diagnostic Patterns

아래 패턴은 자주 나오는 진단 의도를 상품 조합과 연결한 예시다. 질문에 맞는 패턴만 쓰고,
필요하면 일부를 조합한다. 다섯 패턴을 모두 실행하거나 같은 섹션을 항상 출력하지 않는다.

## 1. 거래 활동과 분위기

예: `리센츠 요즘 거래 분위기 어때?`

**알고 싶은 것:** 최근 거래가 활발한지, 어떤 거래 유형과 면적대가 움직였는지, 관측 가능한
가격 신호가 있는지.

**기본 근거:** 단지 상세의 기준월·최근 6개월 요약 + 실거래 계약.

**판단 방법:**

1. 기준월에 맞춘 월별 유효 거래 건수를 먼저 본다.
2. 매매·전세·월세를 나누고 취소 건은 유효 통계에서 제외한다.
3. 단지 전체 가격 범위가 넓으면 면적 혼합 여부를 확인한다.
4. 가격 흐름을 말하려면 같은 전용면적 구간끼리 기간을 비교한다. 그렇지 않으면 거래량과
   관측 범위만 진단한다.
5. 마지막 월은 신고가 덜 쌓였을 수 있으므로 이전 완결월과 같은 강도로 해석하지 않는다.

**피할 결론:** 여러 면적이 섞인 월 중앙값 변화만으로 `가격이 올랐다/내렸다`고 단정,
거래가 적다는 이유만으로 수요가 없다고 원인 추정.

## 2. 실거주 여건과 단지 프로필

예: `헬리오시티 실거주 여건 진단해줘.`

**알고 싶은 것:** 규모, 연식, 주차, 난방, 교통·학교·생활시설 접근성에서 보이는 장점과
제약.

**기본 근거:** 단지 상세. 이 질문은 한 상품만으로 충분할 수 있다.

**판단 방법:**

- 규모와 연식, 세대당 주차대수처럼 같은 단지 행 안에서 의미 있는 파생값만 계산한다.
- 지하철·병원·공원 거리는 `가깝다/멀다`의 제한된 근거로 쓰고 실제 이동시간은 만들지 않는다.
- 배정 학교명은 사실로 제시하되 학업 성취, 선호도, 통학 안전으로 확장하지 않는다.
- 한 개의 종합 점수보다 `대단지 운영 편의`, `교통 접근성`, `주차 여유`, `연식`처럼 근거가
  다른 항목을 나눠 장단점을 쓴다.

**추가 상품 조건:** 주변 분포를 지도에 그려야 할 때만 경계·마커를 붙인다. 가격·실거래는
사용자가 주거비나 시장성까지 물었을 때만 추가한다.

## 3. 지역 시장의 구성과 현황

예: `잠실동 아파트 시장의 단지 구성과 최근 거래 현황을 분석해줘.`

**알고 싶은 것:** 한 지역에 어떤 주거 유형과 규모의 단지가 있는지, 최근 거래가 어디까지
관측되는지.

**기본 근거:** 법정동 검색 + 지역 단지 목록.

**판단 방법:**

1. 지역명을 법정동 코드로 확정하고 같은 이름의 다른 지역을 섞지 않는다.
2. 유형별 단지 수는 법정동 상품의 사전 계산값을 사용한다.
3. 지역 단지 목록을 완전히 수집한 경우에만 세대수·연식·최근 6개월 거래 건수의 지역 분포를
   계산한다. 일부 페이지면 `조회된 단지` 범위로 낮춘다.
4. 아파트·오피스텔·연립다세대는 각각 행의 의미와 가격대가 다르므로 유형을 나눠 설명한다.
5. 지역 현황만 필요한데 모든 단지의 개별 실거래를 반복 호출하지 않는다. 계약 시기나 면적
   구성이 핵심일 때만 필요한 단지를 좁혀 실거래를 추가한다.

**피할 결론:** 단지 수가 많다는 이유로 시장 유동성이 높다고 단정, 유형이 다른 단지의 평균
가격을 한 숫자로 합산.

## 4. 평형·면적 구성

예: `헬리오시티에서 어떤 평형이 주력인지 분석해줘.`

**알고 싶은 것:** 공급 평형과 전용면적 구성이 어떻게 분포하며 어느 구간의 수량이 많은지.

**기본 근거:** 건물 상세의 `units_summary`.

**판단 방법:**

1. 건물별 요약을 펼쳐 공급 평형·타입·전용면적별 수량을 합한다.
2. 구성비 분모는 같은 `units_summary`에서 합한 전체 수량으로 둔다.
3. 공급 평형 라벨은 그대로 보여주고, 전용면적이 겹치는 평형은 가격 분석 시 같은 면적
   밴드가 될 수 있음을 별도로 밝힌다.
4. 상위 평형의 수량과 비중, 타입 다양성, 전용면적 범위를 함께 제시한다.

**추가 상품 조건:** 특정 호·층까지 묻지 않으면 호실 상세를 호출하지 않는다. 단지 프로필의
세대수나 호수와 요약 합계가 달라도 임의로 보정하지 않는다.

## 5. 가격 수준과 가격 근거

예: `래미안 원베일리 34평 가격 수준 진단해줘.`

**알고 싶은 것:** 지정된 면적 범위에서 최근 계약, 현재 산출시세, 공시 기준값이 각각 어떤
구간을 보이는지.

**기본 근거:** 단지 검색 + 건물 평형 요약 + 면적을 맞춘 실거래. 질문에 따라 산출시세와
공시가격을 추가한다.

**판단 방법:**

1. 사용자가 말한 평형을 건물 요약의 실제 공급 평형과 전용면적 범위에 연결한다. 평×3.3
   같은 계산으로 전용면적을 추정하지 않는다.
2. 실거래는 같은 거래 유형과 면적 범위의 유효 계약만 모아 건수·중앙값·범위를 본다.
3. 산출시세는 해당 면적대의 최신 스냅샷 분포로, 공시가격은 같은 면적대 또는 명시된 호의
   공시 기준 분포로 각각 표시한다.
4. 표본이 적으면 개별 계약을 보여주고 대표가격의 확신을 낮춘다.
5. 세 가격 근거의 기준시점과 목적을 각각 적는다. 평균을 내거나 공시가격 대비 배수 하나로
   `적정가`를 단정하지 않는다.

특정 호가 질문의 대상이면 `jpk`로 산출시세와 공시가격의 물리적 대상을 맞출 수 있다. 다만
호가 지정되지 않은 질문에 임의의 대표 호를 필수로 고르지 않는다.

## 패턴을 조합할 때

- 거래 분위기 + 가격 수준: 먼저 거래량을 전체 범위에서 보고, 가격은 면적대를 나눠 본다.
- 실거주 + 가격: 생활 근거와 가격 근거를 별도 섹션으로 두고 하나의 점수로 합치지 않는다.
- 지역 구성 + 특정 단지: 지역을 배경으로 제시하되, 단지 값과 지역 집계를 같은 행 단위처럼
  평균내지 않는다.
- 평형 구성 + 거래: `units_summary`의 공급 비중과 실거래의 계약 비중은 서로 다른 모집단이다.
  `공급이 많아서 거래가 많다`는 인과를 데이터만으로 확정하지 않는다.

## 근거 강도 표현

`높음/보통/낮음` 같은 신뢰도 라벨을 쓸 때는 느낌이 아니라 다음 데이터 상태로 설명한다.

- **충분:** 대상과 범위가 맞고, 필요한 페이지가 완결되며, 표본과 기준시점이 결론을 지지함.
- **제한적:** 표본이 적거나 일부 페이지만 조회했지만 관측 범위 안의 설명은 가능함.
- **판단 보류:** 핵심 상품이 비어 있거나 면적·유형·시점을 맞출 수 없어 결론이 왜곡됨.

데이터가 제한적이면 리포트를 억지로 풍성하게 만들지 말고 확인 가능한 사실과 확인 불가능한
판단을 분리한다.
