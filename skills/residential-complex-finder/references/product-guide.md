# 조건에 필요한 상품만 선택한다

이 문서는 상품의 역할과 연결 주의점을 설명한다. 필터·필드 전체나 페이지 한도 사본이 아니다.
호출 전 현재 MCP 입력 계약과 상품 메타데이터, 또는 `https://datamarket.bigvalue.ai/llms.txt`에
연결된 최신 문서에서 필요한 필드와 반환 단위를 확인한다.

## 단지 수준에서 시작하고 필요한 근거만 추가한다

| 질문에 필요한 근거 | 공개 상품 문서 / MCP 도구 | 사용 방법 |
|---|---|---|
| 지역·단지 이름 식별 | `residential-location-search.md` / `search_residential_locations` | `result_type`과 지역 설명으로 대상을 정한다. 단지 `result_key`는 `complex_key`로 연결한다. 검색 목록 자체는 지역 전체 단지 목록이 아니다. |
| 행정 범위·지역 구성 | `region-legaldongs.md` / `legaldong_search` | 선택 지역의 상세·유형별 규모가 필요할 때 사용한다. 경계 도형 제공 여부와 지역 목록 조회 가능 여부는 별개다. |
| 지역 후보, 규모·연식·주차·시설 거리 등 | `residential-complexes.md` / `complexes_by_region`, `complex_profile` | 같은 상품의 지역 목록·개별 진입이다. 필터에 없는 조건도 반환 필드로 판정한다. 최근 매매 요약은 단지 전체 기준이다. |
| 동 규모·호실 조회 키 | `residential-buildings.md` / `building_summaries` | 동 이름·층수·호실 수와 `ppk`를 확인한다. |
| 특정 층·호·전용면적의 존재 | `residential-units.md` / `unit_details` | 단지 키와 건물 키 또는 호 키로 조회한다. 조건을 충족한 실제 호가 확인되면 존재 근거로 쓰고, 일부 조회에서 찾지 못한 것을 부재로 단정하지 않는다. |
| 특정 시기·면적·금액의 계약 관측 | `residential-realdeal.md` / `realdeal_history` | 거래 유형·기간·면적·금액을 같은 계약에 적용하고 취소 거래를 제외한다. 존재 여부와 평균·건수 조건은 필요한 수집량이 다르다. |
| 특정 호·면적의 현재 추정 금액 | `residential-estimated-prices.md` / `estimated_prices` | 같은 호의 면적과 산출시세를 판정한다. 층 조건이 필요하면 `jpk`로 호 상세에 연결한다. 하한·대표값·상한 중 어떤 가격을 썼는지 밝힌다. |
| 공시 기준 금액 | `residential-notice-prices.md` / `notice_prices` | 해당 연도와 호·면적을 맞춘다. 매수 예산이나 시장가격의 대용으로 쓰지 않는다. |
| 공간 분포·대표 유형 | `residential-complex-type-markers.md` / `residential_type_markers` | 단지 1행이며 `residential_type`은 대표유형이다. 공간 범위·잘림을 확인하며, 지도 표현이 없으면 거리 조건만을 위해 자동 호출하지 않는다. |
| 단지 경계 도형 | `residential-complex-shapes.md` / `complex_area` | 실제 공간 포함·도형 판정이나 요청한 지도 표현에 필요한 경우에만 쓴다. |

## 반환 행의 단위를 보존한다

- 단지 `complex_key`, 지역 법정동 코드, 지번 `pnu`, 건물 `ppk`, 호 `jpk`는 문자열이다.
  이름이나 배열 순서로 조인하지 않는다. 단지 후보는 `complex_key`로 중복 제거한다.
- 동·읍·면·리는 확정한 지역의 10자리 법정동 코드, 시군구와 시도는 각각 해당 코드의
  5자리·2자리 접두어를 사용한다. 검색 결과가 잘렸거나 이름이 같으면 자동 병합하지 않는다.
- `unit_details`는 단지 키만으로 조회할 수 없다. 필요한 건물·호를 식별한 뒤 내려간다.
  가격 상품이 면적과 필요한 값을 이미 반환하면 불필요한 호 조회는 생략할 수 있다.
- 호·가격 결합은 반환 식별자와 면적·시점을 대조한다. 실거래에는 `ppk`·`jpk`가 없으므로
  면적이나 층이 같다는 이유로 특정 호에 연결하지 않는다.

## 조건을 필터와 동일시하지 않는다

| 분류 | 처리 |
|---|---|
| 서버가 직접 지원하는 조건 | 입력 계약의 필터로 먼저 줄이고 반환 행도 범위 안인지 확인한다. |
| 반환 필드로 확인 가능한 조건 | 필요한 행을 수집해 로컬에서 판정한다. 난방 방식이나 거리 조건이 필터에 없다는 이유만으로 불가능하다고 하지 않는다. |
| 계산·연결이 필요한 조건 | 분자·분모·행 단위·시점을 먼저 정한다. 예를 들어 주차 대수/세대수는 같은 단지 행의 양수 분모일 때만 계산한다. |
| 제공되지 않는 근거 | 확인 불가로 남긴다. 사용자 승인 없이 유사한 다른 조건으로 대체하지 않는다. |

대표 유형이 아파트인 단지를 찾는 것과 아파트가 일부 포함된 모든 단지를 찾는 것은 다르다.
현재 공개 상품은 전체 포함 유형 목록을 제공하지 않으므로 후자를 완전하게 판정할 수 없다.
대표유형 기준 후보라고 범위를 밝히고, 마커만 쓸 경우 검색 영역과 반환 상한에 따른 누락도
함께 설명한다.

## 가격·면적·기간의 의미를 먼저 정한다

- ‘예산 안’이 최근 계약, 현재 산출시세, 호가 중 무엇을 뜻하는지 불분명하면 확인한다.
  현재 매물·호가는 제공하지 않는다. 가능한 대체 근거를 설명할 수는 있지만 조용히 치환하지 않는다.
- 같은 면적의 거래가 한 건 있었다는 사실과 그 면적의 평균 가격이 예산 이내라는 주장은 다르다.
  금액 필터로 예산 이내 거래만 모아 그 평균을 전체 평균이라고 쓰지 않는다.
- 공급 평형과 전용면적을 구분한다. 공급 평형만으로 거래 면적을 결정할 수 없으면 실제
  면적 근거를 확인하거나 전용면적 조건을 질문한다. 실거래를 특정 공급 평형에 귀속하지 않는다.
- 매매 금액, 전세 보증금, 월세 보증금·월 납입액을 구분한다. 필드의 null을 다른 가격 축으로
  메우거나 임의 환산율로 통합하지 않는다.
- 각 상품의 실제 기준월·연도·관측 기간을 유지한다. 최신 호 가격의 한 시점으로 과거 변화나
  추세를 만들지 않는다. 단지 요약과 상세 행이 다른 시점이면 해당 조건의 한계로 표시한다.

## 제공하지 않는 사실은 남겨 둔다

현재 매물 여부, 중개 연락처, 실제 도보 경로·시간, 학군 서열, 조망·소음·일조, 미래 개발·수익률은
이 상품들의 값만으로 확정하지 않는다. 별도 근거가 연결되면 출처·대상·시점을 확인해 조건에
추가할 수 있지만, 이 스킬이 그 외부 데이터를 기본 제공한다고 약속하지 않는다.
